FloatChat — Oceanographic AI Platform

A RAG-powered platform enabling plain-English queries over ARGO float ocean data — built for Smart India Hackathon 2024, targeting policymakers and NGOs with no data-science background.

Role
Sole developer
Timeline
SIH 2024 / 2025
Stack
Python · LangChain · LLaMA-3-8B · MCP · FAISS · PostgreSQL · NetCDF
Links
GitHub repo

TL;DR

  • ARGO float NetCDF files ingested into PostgreSQL, queryable in plain English via LLaMA-3-8B and RAG.
  • Semantic search over all-MiniLM-L6-v2 embeddings in FAISS; MCP protocol for context-aware tool calls.
  • Interactive visualisations (float trajectories, depth profiles) make ocean science accessible to non-technical stakeholders.

Problem

ARGO float data — the global ocean observing network's crown jewel — is distributed as NetCDF files: a binary, multi-dimensional format with no natural-language interface. Oceanographers can query it; policymakers, NGOs, and journalists cannot. Smart India Hackathon 2024 posed the challenge: make this data accessible without requiring data-science skills.

Constraints

  • No external ocean-data API — must ingest raw NetCDF via FTP.
  • Queries must remain grounded in actual float data (no hallucination).
  • Visualisations must render in a browser with no specialist libraries on the client side.

Approach

The pipeline has three stages: ingest, retrieve, respond.

Stage 1 — Ingest: ARGO float files are fetched via FTP, parsed with xarray (NetCDF format), and stored as structured rows in PostgreSQL — covering temperature, salinity, pressure, and geographic coordinates by float ID and date.

Stage 2 — Retrieve: User queries are embedded with all-MiniLM-L6-v2 and matched against a FAISS vector index of float-profile summaries. The top-k results provide grounded context for the LLM.

Stage 3 — Respond: LLaMA-3-8B (via LangChain) synthesises a natural-language answer from the retrieved context. MCP exposes structured tool calls — allowing the model to request specific depth profiles or trajectories as follow-ups, then renders interactive visualisations in the UI.

Technical implementation details
  • Embedding model: sentence-transformers/all-MiniLM-L6-v2 (22 MB, runs CPU)
  • Vector store: FAISS with L2 index; persisted to disk for restarts
  • LLM: LLaMA-3-8B via HuggingFace inference (quantized 4-bit for local dev)
  • MCP layer: Exposes get_temperature_profile, get_salinity_profile, list_floats as MCP tools
  • Visualisations: Server-rendered matplotlib figures served as base64 PNG inline
  • Database: PostgreSQL with schema per ARGO parameter set

Outcome

FloatChat successfully demonstrated plain-English access to ARGO float data for non-technical audiences in the Smart India Hackathon context. Users could ask questions like "What was the sea surface temperature near 12°N 80°E in March 2024?" and receive grounded, cited answers with trajectory maps.

Qualitatively: the RAG pipeline eliminated hallucinated ocean coordinates — every answer traced back to an actual ARGO float record.

What I learned

  • NetCDF spatial data requires careful chunking before vectorisation — naive full-file embedding was 40× slower.
  • MCP's tool-call interface let the LLM request follow-up data without prompt-stuffing the context window.
  • Non-technical users needed visualisations, not just text — the trajectory maps were the most-cited feature in feedback.
